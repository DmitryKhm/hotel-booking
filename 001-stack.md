# ADR 001 — Стек и границы модулей

Статус: принято.

## Контекст

Нужна воспроизводимая учебная система с REST, JPA, JWT, обнаружением сервисов и Gateway. Сервисам бронирования и каталога нужны локальные транзакции; Gateway нужен неблокирующий HTTP-прокси. Среда должна запускаться без внешней СУБД и брокера.

## Решение

Использовать Java 21 как базовый language/bytecode level, Spring Boot 3.5.16 и совместимую линию Spring Cloud 2025.0.3. Сборку фиксируют родительский Maven POM и Maven Wrapper. JDK 25 допускается как дополнительная среда при сохранении `release=21`; preview API не используются.

Booking и Hotel используют MVC, JPA/Hibernate и по одной H2 in-memory. Gateway использует Spring Cloud Gateway Server WebFlux. Eureka выделена в четвёртый процесс. Общая инфраструктура MVC хранится в `common`; Gateway не подключает этот модуль, сохраняя реактивный стек изолированным от Servlet.

Для синхронного обращения Booking к Hotel используется `RestClient` со Spring Cloud LoadBalancer и отдельной политикой Retry/Timeout/Circuit Breaker. Swagger/OpenAPI описывает HTTP-контракты бизнес-сервисов. JUnit 5, MockMvc, WebTestClient и реальные транзакции H2 проверяют поведение; Spotless проверяет единый формат Java-кода.

## Последствия

Четыре приложения можно запускать локально через `java -jar` или Compose. Реестр не требует ручного указания текущих адресов экземпляров при штатном запуске. Отдельный `common` уменьшает дублирование ошибок и безопасности, не создавая общую бизнес-модель.

H2 упрощает демонстрацию, но данные и восстановление теряются при остановке процесса. JPA-блокировки проверяют выбранный алгоритм в учебной БД; перед промышленным использованием требуется повторить конкурентные тесты на целевой СУБД. JDK 25 не делает проект зависимым от возможностей Java 25 и не заменяет проверку `mvnw verify` в выбранной среде.

Рассмотренные альтернативы: одна программа с общей БД не демонстрирует межсервисную согласованность; WebFlux в JPA-сервисах добавил бы смешение блокирующих и реактивных операций; брокер и Kubernetes усложнили бы локальный запуск без необходимости для заданных сценариев.
