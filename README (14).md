# Hotel Service

Самостоятельное Spring Boot приложение на порту `8082`, Eureka ID `hotel-service`.
H2 находится только в памяти процесса. Данные и ключи идемпотентности исчезают после перезапуска.

## API

Все маршруты, кроме health и OpenAPI, требуют JWT. Права проверяются внутри сервиса через `@PreAuthorize`.

| Метод и путь | Доступ | Назначение |
|---|---|---|
| GET `/api/hotels` | USER, ADMIN | Поиск по `search`, пагинация `page`/`size`, `sort=id,name,address` |
| GET `/api/hotels/{id}` | USER, ADMIN | Один отель |
| POST `/api/hotels` | ADMIN | `{ "name": "Hotel", "address": "Address" }` |
| PUT/PATCH `/api/hotels/{id}` | ADMIN | Замена/обновление отеля |
| DELETE `/api/hotels/{id}` | ADMIN | Мягкое удаление отеля и номеров |
| GET `/api/hotels/statistics` | ADMIN | Статистика за `startDate`, `endDate`, необязательный `hotelId` |
| GET `/api/rooms` | USER, ADMIN | Свободные номера за обязательные даты; `hotelId`, пагинация, `sort=id,number,timesBooked` |
| GET `/api/rooms/recommend` | USER, ADMIN, INTERNAL | Массив свободных номеров, порядок `timesBooked ASC, id ASC` |
| GET `/api/rooms/inventory` | ADMIN | Все номера, включая ремонт; `hotelId`, пагинация |
| GET `/api/rooms/{id}` | USER, ADMIN | Один номер |
| POST `/api/rooms` | ADMIN | `{ "hotelId": 1, "number": "101", "available": true }` |
| PUT/PATCH `/api/rooms/{id}` | ADMIN | Замена/обновление номера; смена отеля запрещена |
| DELETE `/api/rooms/{id}` | ADMIN | Мягкое удаление номера |
| POST `/api/rooms/{id}/confirm-availability` | INTERNAL | Атомарное резервирование интервала |
| POST `/api/rooms/{id}/release` | INTERNAL | Идемпотентная компенсация |

Последние два маршрута не должны публиковаться Gateway. ADMIN не получает роль INTERNAL.
Тело внутренних запросов: `{ "requestId": "UUID", "bookingId": 1, "startDate": "2027-01-10", "endDate": "2027-01-12" }`.

## Согласованность и данные

- Даты задают полуоткрытый интервал `[startDate, endDate)`: выезд одного гостя и заезд следующего допустимы в один день.
- `available` обозначает эксплуатационную доступность. Занятость по датам хранится отдельно в `room_reservations`, локальной проекции бронирований Booking Service.
- Проверка пересечения и вставка слота выполняются в одной локальной транзакции под `PESSIMISTIC_WRITE` блокировкой строки номера. Разные номера не блокируют друг друга.
- Уникальный ключ `(room_id, request_id)` и проверка исходного payload защищают от повторов и повторного использования ключа с другим запросом.
- Компенсация сохраняет запись `RELEASED` даже до получения исходного запроса. Позднее подтверждение получает `409 RESERVATION_RELEASED`. Поэтому потеря ответа и перестановка запросов не создают занятый слот после отмены.
- `timesBooked` увеличивается один раз при подтверждении слота и уменьшается один раз при компенсации/отмене. Завершённые, не отменённые бронирования остаются в счётчике.
- Мягкое удаление сохраняет историю и ключи повторов. Отель/номер с будущими либо текущими бронированиями удалить нельзя (`409`).
- Статистика пересекает интервалы с выбранным периодом и возвращает занятые ночи, вместимость и процент загрузки. Знаменатель включает все неудалённые номера, в том числе находящиеся сейчас на ремонте; исторический календарь ремонтов в учебной модели не ведётся.
- Демоданные: два отеля, шесть номеров, один на ремонте и три исторических слота с отрицательными демонстрационными `bookingId` (это предыстория, не реальные записи Booking Service). Отключение: `DEMO_DATA=false`.

OpenAPI: `/v3/api-docs`; Swagger UI: `/swagger-ui.html`.

## Проверка

Из корня проекта: `./mvnw -pl hotel-service -am test` (Windows: `mvnw.cmd`).
Интеграционные тесты проверяют параллельные пересекающиеся брони, повторную доставку, компенсацию до подтверждения,
смежные даты, сортировку рекомендаций, статистику, CRUD, валидацию и разграничение 401/403.
